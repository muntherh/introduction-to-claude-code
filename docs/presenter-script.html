Introduction to Claude Code — Presenter Script

16 slides ~60 min 12 interactive slides 1 slide needs internet

Everything in an orange block is written to be said out loud, exactly as it is. The sentences are short on purpose — about one breath each — so you can look down, take a line, and look back up at the room. The grey lines are for you only. Do not read those.

Before you start

  • Open the site and press f for full screen.
  • Press one arrow forward and one back, to check that it responds.
  • o opens the slide list if you need to jump.
  • The deck needs no internet. Everything in it is simulated locally.
  • Slide 08 does. That is where the room installs Claude Code. Check the wifi before you begin.
  • Run node -v on your own machine. Anything under 18 will fail the install, and you want to know that before the room asks.
  • Have a real project folder open in a second terminal, in case someone asks you to try their idea.
01 Welcome 2 min · 00→02

“Welcome. This is an introduction to Claude Code.”

“Claude Code is an AI that works inside your project.”

“Not beside it in a browser tab. Inside it.”

“In the next hour you will install it.”

“You will talk to it, and let it change real files.”

“And you will not write a single line of code.”

Do Press f for full screen before the room settles. Then press Start, or the right arrow.
Bridge“So let us start with the simplest question. What is it?”
02 What is Claude Code? Audience 4 min · 02→06

“Claude Code is Claude, running in your terminal.”

“It can read the project you are standing in, and change it.”

“Five things are worth knowing. Let us open three.”

“A teammate, not a search box. You say what you want. It does the work.”
“It sits inside your project. The folder you start it in is everything it can see.”
“It asks before it acts. Nothing on your machine changes without your yes.”
Do Open three cards, not five. Leave two for the room to find later — a slide you did not exhaust is a slide they go back to.
Bridge“Two of those said the word terminal. Let us look at what that means.”
03 It lives in your terminal 3 min · 06→09

“This is the whole interface. One black window.”

“No tabs. No dashboard. No upload button.”

“You open it inside a folder, and that folder is the project.”

“You type plain English. There is nothing to memorise.”

“And it stays open while you work, so it remembers the last hour.”

Pause here. Look at the room before the next two lines.

“The terminal looks unfriendly. That is the only hard part of today.”

“Once it is open, everything after this is a conversation.”

Do Point at the blinking cursor. Do not type anything yet — slide 08 is where the room opens their own, and doing it twice flattens that moment.
Bridge“So what actually happens when you type into that window?”
04 How it works 3 min · 09→12

“Every task follows the same four beats.”

“You ask. One task, in plain words.”
“It looks. It opens the files that matter, first.”
“It changes. It edits, and shows you which lines moved.”
“You check. You say what is still wrong.”

“That last line becomes the next task. That is the loop.”

“Look at beat two. It reads before it writes.”

Do Let the four steps reveal one at a time and do not talk over them. If you narrate ahead, the room reads step four while you are still on step one.
Bridge“That second beat is the whole difference. Let me show you it happening.”
05 It reads your real project Audience 4 min · 12→16

“Here is a real project. Let us ask it something.”

Take a question from the room, or pick the one about the contact form.

“Watch what happens before the answer arrives.”

Stay quiet while the Read lines appear. The silence is the teaching.

“It opened two files. Then it answered.”

“A chat window cannot do that. It has never seen your files.”

“So it would have guessed. And it would have guessed wrong.”

Do Click one question and let the reveal run to the end without commentary. If you have time, run a second one.
Bridge“Which raises the obvious question. When do you use which?”
06 A chat window vs Claude Code Audience 4 min · 16→20

“Same Claude underneath. The difference is access.”

“A chat window runs in a browser tab. Good for learning.”

“Claude Code runs inside your project. Good for changing it.”

“Four tasks. You tell me which one.”

Read each task out loud and wait for the room before you click.

“One question sorts all four.”

“Does it need to open my files?”

Do Ask for hands. Do not answer for them — this is the first slide where the room commits to an opinion, and it sets the tone for the rest of the hour.
Bridge“Before we install it, there is one more thing you need to trust.”
07 You are in control Audience 4 min · 20→24

“Claude Code stops and asks before it touches anything.”

“Four requests. Let us refuse one on purpose.”

Press Refuse. Then wait a beat before the next line.

“Nothing happened. The file is exactly as it was.”

“Saying no is a normal answer, not a failure.”

“Read the line before you press yes.”

“Especially anything that installs something, or deletes something.”

Do Refuse at least one, and make sure the room sees that nothing broke. A beginner who has watched a refusal do nothing is a beginner who will actually run the tool.
Bridge“Right. Open your laptops. This is where you start typing.”
08 Install and start Audience Internet 7 min · 24→31

“Three lines. Everyone types them now.”

“The first installs it, once, on your machine.”

“The second goes into the folder you want to work on.”

“The third starts it.”

Wait for the whole room. Do not move on early.

“You need Node version eighteen or newer.”

“If the first line fails, that is almost always why.”

“To leave, type slash exit. Your files stay exactly as they were.”

Do Run each line on screen as the room runs it, and walk between the desks. This is the slide where you lose people if you rush — everything after it assumes they are in.
Bridge“Everybody in? Good. Now ask it for something.”
09 Your first session Audience 5 min · 31→36

“Type a request and watch the whole turn.”

“It reads. It decides. It edits. It reports back.”

Let the turn finish before you say the next line.

“Look at how much of that was reading.”

“That is not the tool being slow.”

“That is the tool refusing to guess.”

Do Send one of the three suggestions first. Then ask the room for a request and type theirs — a turn they wrote lands harder than one you prepared.
Bridge“The request is the only part you control now. So let us make yours good.”
10 What a good request looks like 5 min · 36→41

“You do not control the code any more. You control the request.”

“So this is the one skill worth an hour of your life.”

“Say what, and say where. One task, and the exact place it goes.”
“List what it must do. Anything you leave out, it decides for you.”
“Point at something that already exists. That is the line a chat window cannot use.”
“Say how you want to work. For a beginner, that line is worth all the others.”
Do Press Explain It and hover each line as you say it. Then press Compare Three and let the room pick before you reveal the answer.
Bridge“And that fourth line — how you want to work — has its own slide.”
11 Read the plan first Audience 4 min · 41→45

“For anything bigger than a one-line change, ask for a plan.”

“This is the plan. It is a draft addressed to you.”

“Delete a step you did not want.”

“Reword one that is vague.”

Edit a step in front of them, then remove one.

“Fixing a wrong step is cheap.”

“Fixing a wrong pile of code is not.”

Do Remove step one and let the room watch the numbering fix itself. That small thing is what makes the plan feel editable rather than official.
Bridge“That plan lasts one task. Some rules should last forever.”
12 CLAUDE.md Audience 4 min · 45→49

“This is a file of house rules.”

“Claude Code reads it before every single task.”

“Try to break one.”

Click a rule. Then click a second one.

“It refuses, and it tells you which rule stopped it.”

“Write these once. They hold for every session after.”

“Put in how to run the project, the style you want, and what is off-limits.”

Do Click two rules, not one. The room needs to see it refuse twice before they believe the first one was not a trick.
Bridge“Almost everything here is plain English. Five things are not.”
13 Five commands to remember 3 min · 49→52

“Five things to remember. Two of them will carry you.”

“Slash init. Run it once in a new project. It writes that rules file for you.”
“Slash clear. Use it when you move to a new task and the old one is just noise.”
“Slash help. Lists everything else. So there is nothing to memorise.”

“And escape, twice, stops it in the middle of a task.”

“You will want that more often than you expect.”

Do Open /init and /clear. If you are behind, this is the slide to move through fastest.
Bridge“Last piece. Getting the work off your machine.”
14 From a change to a pull request 3 min · 52→55

“The part that frightens beginners most is git.”

“It is now the part you never have to do by hand.”

“You describe the change. Still plain English.”
“It saves your work. And writes the message describing it.”
“It sends it to GitHub. On a new branch, so the live site is safe.”
“It opens the pull request. Ready for someone to review.”
Say this last line only after the fourth step has landed.

“You never typed a git command. You described four outcomes.”

Do Let the four beats reveal at their own pace. If someone wants to learn git properly, tell them to ask Claude Code to explain each step on their own project.
Bridge“Five quick questions, and then you are done.”

Read each question, wait for the room, then click.

Questions you should expect

So we do not need to learn programming any more?

“You need it less to start, and more to judge. Claude Code writes the code. You still decide whether it is right. Reading code just became the more valuable half of the job.”

Is it free?

“Claude Code is a paid product, and there are plans that include it. Prices change, so check claude.com slash claude-code rather than trusting my number from today.”

Can it break my project?

“It can change files, yes. That is why it asks first, and why you keep your work in git. With git, anything it did is one command away from being undone. Without git, be much more careful about what you approve.”

Does it send my code to Anthropic?

“It sends the parts it reads, because that is how it answers you. If your project is sensitive, check your organisation's policy before you point it at real code. That is a fair question to ask before you install anything.”

Why the terminal? Can I not have a proper window?

“Because your project already lives there — the files, git, and the commands that run it. Putting Claude Code in the terminal is what lets it touch all three. There are editor extensions too, but the terminal is the one to learn first.”

What if it does something I did not ask for?

“Tell it. That is the fourth beat of the loop. You say what is wrong and it fixes it, in the same conversation. You do not start over.”

If something goes wrong

The internet drops

Only slide 08 needs it, for the install. Every other slide is simulated locally and will behave exactly as normal. If the room cannot install, present slides 08 to 14 as a demo on your own machine and tell them to install at home — the starter prompt on slide 16 is what they run then.

Someone's install fails

It is almost always Node. Have them run node -v; anything under 18 is the cause. Pair them with a neighbour and keep going — debugging one laptop live loses the other twenty.

You are running out of time

Cut slide 13 first, then slide 14. Never cut 07, 08 or 10. Slide 07 is what makes a beginner willing to run the thing at all. Slide 08 is the only place they touch it themselves. Slide 10 is the one skill the workshop exists to teach.

The room is silent

Jump to slide 06, read one task out loud, and ask for a show of hands: chat window, or Claude Code? A closed question restarts a room much faster than an open one.

The room is more expert than you expected

Compress slides 02 to 07 into about ten minutes and spend what you save on 10, 11 and 12. Then ask someone with a real project to give you the request on slide 09 — an expert room engages with a real example, not a prepared one.

A slide looks slightly cut off

On a 1280×720 laptop, six slides carry one closing line below the fold. Scroll a nudge or press the down arrow. Nothing you need to click is ever below the fold — that is checked by npm run verify:fit.
